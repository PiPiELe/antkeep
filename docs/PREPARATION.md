# 蚁记 AntKeep · 开发准备

状态：仅完成仓库及方案准备，尚未进入应用编码。
目标平台：Android、iPhone；微信小程序暂不开发。

## 产品定位

面向个人及蚂蚁爱好者的本地养殖记录工具。无需注册或登录，核心功能断网可用。
养殖记录和照片保存在设备本地，首版不建设业务服务器、不上传养殖数据、
不接入广告、行为统计、远程日志或云同步。

## 首版范围

| 模块 | 计划功能 |
| --- | --- |
| 蚁群档案 | 昵称、品种、入手日期、来源、蚁后数量、巢体类型、封面 |
| 日常记录 | 投喂、补水、观察、温湿度、换巢、繁殖、死亡、备注 |
| 成长时间线 | 按实际发生时间排列图文记录；卵、幼虫、蛹、工蚁数量支持未知及估计 |
| 快速记录 | 常用事件快捷录入；同次操作可选择多个蚁群 |
| 待办 | 养护计划、完成记录、设备本地通知 |
| 数据管理 | 存储占用、导出备份、恢复备份、换机迁移 |

首个可运行里程碑：创建蚁群 → 添加图文记录 → 查看时间线 → 导出备份 → 在空库恢复。
其后加入批量记录、成长统计与本地养护提醒。

页面规划：蚁群、记录、待办、设置；蚁群详情内提供时间线。

## 技术方向（待工程验证）

- Flutter / Dart：共享 Android 与 iOS 界面及业务逻辑。
- SQLite：保存结构化记录；数据库升级使用明确的版本迁移。
- 应用私有目录：保存照片独立副本，记录使用相对路径，不依赖相册原文件。
- 本地通知：不使用服务器推送；权限被拒绝时仍能使用待办清单。
- 将持久化、图片导入导出、通知与界面分离，保持结构简单。
- 依赖版本待 SDK 安装并验证兼容性后锁定，不提前承诺最新版本。
- 正式业务包不添加无必要的网络能力；开发调试连接与业务联网需要区分。

## 数据原则与恢复安全

1. 未知数量与零分开保存；估计值不能伪装成精确计数。
2. 事件发生时间与创建、修改时间分开，支持补记过去的养殖事件。
3. 每条记录使用稳定 ID，归属明确的蚁群；蚁群归档应保留历史记录。
4. 一次批量记录应在数据库事务中完成，避免仅部分蚁群保存成功。
5. 照片必须复制成功后才能形成有效引用；处理应用重启及磁盘空间不足。
6. 备份包含格式版本、数据清单及引用照片；Android / iOS 使用同一可移植格式。
7. 首版恢复采用整库恢复，不做跨设备自动同步或复杂合并。
8. 恢复前先校验版本、字段、关联关系、附件完整性、路径与体积限制。
9. 先在临时位置完成准备，验证成功后再切换；失败不能破坏现有记录。
10. 覆盖现有数据需要应用内明确提示，并在覆盖前保留本地回退副本。
11. 手动导出的备份属于用户文件；应用不自动发送到网盘或其他服务。
12. 平台系统云备份需明确排除：Android 检查备份及设备迁移规则，
    iOS 检查持久化目录的备份排除属性。具体效果需要真机验证。
13. 本地保存不等于已做数据库加密；首版不宣称额外的应用级加密能力。
14. 卸载、设备损坏可能导致本地数据丢失；提供清楚的备份提醒与恢复入口。

## 开发顺序

1. 准备稳定版 Flutter、Android SDK、完整 Xcode 及所需平台依赖。
2. 拉取远程，按 AGENTS.md 从远程 master/main 创建需求分支。
3. 生成 Android / iOS 工程，建立主题、导航与本地数据层。
4. 实现首个可运行闭环，并验证应用重启后的记录与照片。
5. 完成备份恢复，包括损坏、版本不兼容、附件缺失及恢复失败场景。
6. 加入待办与本地通知，再加入批量记录及基础成长统计。
7. 执行静态分析、自动化测试和两端真机检查后，提供内测包。
8. 上架、签名证书、商店账号与正式发行属于后续交付环节。
